# گزارش کنترل کیفیت فرانت‌اند کاتالوگ — v1

**تاریخ:** ۱۷ مرداد ۱۴۰۵  
**دامنه:** مرحله‌های ۱ تا ۶ تاکسونومی، متادیتا، کتابخانه، جست‌وجو، جزئیات محصول و مسیر تکمیل داده.  
**محدودیت محیط QA:** مرورگر خودکار/Chromium در محیط اجرا در دسترس نبود؛ کنترل responsive به‌صورت بررسی ساختار CSS، اجرای TypeScript، build، تست مسیر HTTP و بررسی کد انجام شده است. پیش از نمایشگاه، یک بازبینی بصری دستی روی گوشی واقعی و Safari iOS نیز لازم است.

## ۱. کنترل مسیرها

| مسیر | انتظار | نتیجهٔ فنی |
|---|---|---|
| `/library` | ۱۰ خانوادهٔ اصلی | مسیر SPA معتبر |
| `/library/doors-windows-openings` | زیر‌دسته‌های همان خانواده | مسیر SPA معتبر |
| `/library/doors-windows-openings/windows` | صفحهٔ تخصصی و Empty State صادقانه | مسیر SPA معتبر |
| `/library/preview/sample-window-metadata-001` | Preview داخلی، غیرعمومی | مسیر SPA معتبر |
| `/catalog-completion-preview/sample-window-metadata-001` | Preview مسیر تکمیل برند، غیرعمومی | مسیر SPA معتبر |
| `/categories` | هدایت به `/library` | مسیر Legacy کنترل شده |

## ۲. RTL و Responsive

| بخش | کنترل انجام‌شده | نتیجه |
|---|---|---|
| Library root | Grid با `sm` و `xl`، متن و کارت‌های `text-start` | مناسب ساختار RTL/LTR |
| زیر‌دسته‌ها | Grid `sm:grid-cols-2` و `lg:grid-cols-3`، مسیر breadcrumb | مناسب ساختار موبایل تا Desktop |
| Filters | sidebar در `lg` sticky و در اندازه‌های کمتر تک‌ستونه | بدون وابستگی به عرض ثابت Desktop |
| صفحهٔ محصول | Header و بدنه از `xl:grid` به تک‌ستون تبدیل می‌شوند | مناسب موبایل/تبلت |
| جدول مشخصات | overflow و سلول‌های wrap شده | باید روی Safari iOS بصری بازبینی شود |
| پنل تکمیل | کارت‌ها و Taskها Flex-wrap و تک‌ستونه‌اند | مناسب موبایل/RTL |

## ۳. دسترس‌پذیری رنگ و تعامل

- CTA Empty State از `#087F7A` با متن سفید استفاده می‌کند؛ رنگ `#0FB9B1` برای متن سفید کوچک استفاده نشده است.
- CTAهای اصلی کتابخانه از `#0F3D5E` یا `#087F7A` استفاده می‌کنند.
- رنگ زعفرانی فقط برای هشدار Preview و Task تکمیل‌نشده است؛ متن روی زمینهٔ زعفرانی، تیره است.
- تمام کنترل‌های تعاملی جدید `button` یا `input/select` واقعی هستند، نه `div` قابل کلیک.
- فیلترهای select label متنی دارند؛ بهبود بعدی پیشنهادی: افزودن `id/htmlFor` و تست screen reader در مرحلهٔ طراحی فرم برند.

## ۴. صداقت و دادهٔ ساختگی

- `PUBLISHED_CATALOG_PRODUCTS` عمداً خالی است.
- `filterCatalogProducts` علاوه بر وضعیت انتشار، `isSample` را نیز مسدود می‌کند.
- دادهٔ Preview برچسب صریح غیرعمومی دارد و در کتابخانه و جست‌وجوی عمومی وارد نمی‌شود.
- وقتی دادهٔ واقعی وجود ندارد، گزینهٔ فیلتر، تعداد ساختگی، برند یا محصول نمونه نمایش داده نمی‌شود.
- وضعیت BIM، Badge سطح داده و وضعیت بررسی از هم جدا هستند.

## ۵. داده‌های ناقص و نامشخص

| وضعیت | رفتار UI |
|---|---|
| Attribute = `unknown` | «اعلام نشده» و عدم امتیاز کامل |
| Attribute = `not_applicable` | «نامرتبط با این محصول» و خروج از مخرج امتیاز |
| BIM در حال آماده‌سازی | بدون دکمهٔ دانلود و بدون زمان/وعده |
| مدرک بدون URL | «لینک عمومی هنوز منتشر نشده» |
| دستهٔ خالی | Empty State و CTA درخواست محصول/برند |
| محصول نمونه | فقط Preview داخلی، هرگز در پاسخ عمومی |

## ۷. موارد لازم پیش از اتصال دادهٔ واقعی

1. تأیید واژگان کنترل‌شده و واحدها برای هر دسته توسط متخصص حوزه.
2. تست دستی Chrome Android، Safari iOS، Desktop Chrome و Firefox.
3. تست واقعی RTL با طول متن زیاد، عنوان طولانی محصول و جدول مشخصات ۲۰+ ردیفی.
4. اتصال یک یا دو برند واقعی در staging، نه محیط عمومی.
5. بررسی امنیت احراز هویت، مالکیت برند، URL امضاشدهٔ فایل و Rate Limit در بک‌اند.
6. اجرای ابزار Accessibility مانند axe پس از در دسترس شدن محیط مرورگر خودکار.

## ۸. موارد بازِ غیرمسدودکننده

- `npm audit --omit=dev` در این محیط ۳ مورد وابستگی گزارش می‌کند: ۱ کم‌خطر و ۲ پرخطر. به‌دلیل امکان تغییر ناخواستهٔ نسخه‌های وابستگی، `npm audit fix` خودکار اجرا نشده است. رضا باید زنجیرهٔ وابستگی و Changelog هر اصلاح را قبل از انتشار بررسی کند.
- فایل JavaScript تولیدشده بزرگ‌تر از آستانهٔ Vite است. قبل از انتشار عمومی، به‌ویژه برای اینترنت موبایل، صفحه‌های Dashboard، Viewer و routeهای سنگین باید با `React.lazy`/`dynamic import` تفکیک شوند.
- تست بصری واقعی روی Chrome Android و Safari iOS هنوز باید انجام شود؛ در این محیط مرورگر headless نصب نبود.
